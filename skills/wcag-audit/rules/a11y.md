# WCAG 2.2 AA Accessibility Rules

Use these definitions as the authority for audit severity and rule IDs. WCAG 2.2 AA is the target. The rules below are review heuristics, not exhaustive automated checks; report only issues supported by code evidence.

## ARIA Rules

1. Prefer native HTML over ARIA substitutes.
2. Do not change native semantics with ARIA.
3. Every ARIA control must be keyboard operable.
4. Never put `aria-hidden="true"` on a focusable element.
5. Every interactive element needs an accessible name.

## Semantic HTML (S1-S8)

| ID | Severity | Detect | Rule | WCAG |
| --- | --- | --- | --- | --- |
| S1 | CRITICAL | `<html>` without `lang` | Set the page language. | 3.1.1 A |
| S2 | SUGGESTION | Multiple unclear page-level `<h1>` elements | Prefer one primary page heading. | Best practice / 1.3.1 |
| S3 | IMPORTANT | Heading levels skip, such as `h1` to `h3` | Maintain logical heading nesting. | 1.3.1 A |
| S4 | IMPORTANT | Page structure uses generic containers without landmarks | Use `header`, `nav`, `main`, and `footer` where applicable. | 1.3.1 A, 2.4.1 A |
| S5 | IMPORTANT | Layout table has no headers, caption, or `role="presentation"` | Use CSS layout, or mark a necessary layout table presentational. | 1.3.1 A |
| S6 | CRITICAL | Data table has rows but no header cells | Add `th` and appropriate scope. | 1.3.1 A |
| S7 | IMPORTANT | Link text is non-descriptive, such as “click here” or “read more” without context | State the link destination or action. | 2.4.4 A |
| S8 | CRITICAL | Non-semantic element handles click interaction | Use a native interactive element. | 4.1.2 A |

## ARIA (A1-A8)

| ID | Severity | Detect | Rule | WCAG |
| --- | --- | --- | --- | --- |
| A1 | SUGGESTION | Redundant native role, such as `<button role="button">` | Remove redundant ARIA. | ARIA rule 2 |
| A2 | CRITICAL | `aria-hidden="true"` on a focusable element | Remove it from focus or use `inert`. | ARIA rule 4 |
| A3 | CRITICAL | ARIA role without required properties | Add the required role properties and state. | 4.1.2 A |
| A4 | CRITICAL | Invalid ARIA role | Use a valid ARIA role. | 4.1.2 A |
| A5 | IMPORTANT | ARIA widget role where native HTML can provide it | Replace with native control. | ARIA rule 1 |
| A6 | CRITICAL | Icon-only button has no accessible name | Add an accurate `aria-label` or visible text. | 4.1.2 A |
| A7 | IMPORTANT | `role="presentation"` on a focusable or interactive element | Remove the presentational role. | ARIA rule 4 |
| A8 | IMPORTANT | Dynamic notification lacks live-region semantics | Use `role="status"`, `role="alert"`, or `aria-live`. | 4.1.3 AA |

Required ARIA properties include `aria-selected` and `aria-controls` for tabs, `aria-expanded` and `aria-controls` for comboboxes, `aria-valuemin`, `aria-valuemax`, and `aria-valuenow` for sliders, and `aria-checked` for checkboxes.

| ID | Severity | Detect | Rule | WCAG |
| --- | --- | --- | --- | --- |

| K2 | CRITICAL | Positive `tabindex` | Use only `0` or `-1`. | 2.4.3 A |

## Keyboard Reference

| Key | Expected behavior |
| --- | --- |
| Tab / Shift+Tab | Move to the next / previous focusable item in DOM order. |
| Enter | Activate links and buttons. |
| Space | Activate buttons; toggle checkboxes; select radio buttons. |
| Escape | Close modals, popovers, menus, and dropdowns. |
| Arrow keys | Navigate composite widgets such as menus, listboxes, radio groups, tabs, sliders, and trees. |
| Home / End | Move to first / last item where the widget pattern calls for it. |

## Audit Checklist by POUR

### Perceivable

- Appropriate image alternatives; captions for prerecorded video.
- Semantic landmarks and coherent heading hierarchy.
- Sufficient text and component contrast; information is not color-only.
- 320-pixel reflow, correct `lang`, and 200% text resize.

### Operable

- Full keyboard access, visible focus, logical focus order, and no traps.
- Skip link; focus remains visible and returns after dialogs.
- 24-pixel touch targets; reduced motion preference is respected.

### Understandable

- Associated form labels, identified and associated errors, semantic required states.
- Error focus/summary and no surprising changes on focus or input.

### Robust

- Accessible name, role, state, and required ARIA properties.
- No focusable `aria-hidden` content; live-region status announcements.
- SPA route changes are announced.
